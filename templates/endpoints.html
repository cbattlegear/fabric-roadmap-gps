GET JSON API

Endpoint: /api/releases

Description: Returns a paginated envelope of releases. Sorted by last_modified (desc) by default, or by release_date (desc) when specified via the sort parameter. Supports filtering, full-text style partial search (simple ILIKE %q%) and page-based navigation. All collection responses are wrapped; a single-item lookup via release_item_id returns just the object (legacy compatibility) without the envelope.

Parameters

  • product_name - Exact match on product name
  • release_type - Exact match on release type
  • release_status - Exact match on release status
  • modified_within_days - Items modified within last N days (1–30)
  • q - Case-insensitive substring search across feature_name, feature_description, product_name. When Azure OpenAI embeddings are configured, q uses vector (semantic) search instead.
  • sort - Sort order: last_modified (default) or release_date
  • page - 1-based page number (default 1)
  • page_size - Items per page (default 50, max 200, min 1)
  • release_item_id - If provided, bypasses pagination and returns a single release object
  • include_inactive - Include releases removed from the roadmap (true or 1). Default: only active releases are returned.

Notes:

  • q trimming applied; empty/whitespace-only search is ignored.
  • When release_item_id is supplied, all other filter / paging parameters are ignored.
  • Stable, stateless pagination: combine your filters + page/page_size; use links.next until it becomes null.
  • Returns Link response header with rel="next"/rel="prev" when applicable.

POST Read-only MCP

Endpoint: {{ mcp_endpoint_url }}

Availability: Included automatically in web mode when this version is deployed, alongside the REST API and RSS feeds. No feature flag or separate server is needed. Host/Origin protections derive from the existing canonical host or base URL; operators should verify Front Door routing as part of deployment.

Connect a compatible AI assistant using Streamable HTTP, not a REST GET or a legacy SSE URL. The official Python SDK is pinned to mcp==2.3.0; initialization and tool calls are exercised on protocol 2025-11-25, with sessionless 2026-07-28 requests also covered. Responses are JSON, stateless, and never publicly cached. Browser/CORS clients and server-to-client streams are not supported.

Connect a client

For Claude Code:

claude mcp add --transport http fabric-gps {{ mcp_endpoint_url }}

Or install mcp==2.3.0 and use the official Python client:

import asyncio
from mcp.client.session import ClientSession
from mcp.client.streamable_http import streamable_http_client

async def main():
    async with streamable_http_client("{{ mcp_endpoint_url }}") as streams:
        async with ClientSession(*streams) as client:
            await client.initialize()
            print(await client.list_tools())
            result = await client.call_tool(
                "search_releases",
                {"query": {"q": "lakehouse", "page_size": 10}},
            )
            if result.is_error:
                raise RuntimeError(result.content)
            print(result.structured_content)

asyncio.run(main())

Available tools

  • search_releases takes a required query object (use {} to list releases). Returns public data, pagination, search_mode: "substring", and page_limit: 100.
  • get_release takes {"release_item_id": "YOUR-ID"}. Returns one public release, including inactive records, with its canonical url.
  • get_release_history takes {"release_item_id": "YOUR-ID", "limit": 10}. Returns newest changes in data, a has_more flag, and the release url. Maximum history depth: 50.
  • get_filter_options takes {}. Returns exact product/type/status values in filters, up to 100 per list, with truncated_filters metadata.

Search parameters and limits

The query object accepts q (up to 200 characters), exact product_name, release_type, and release_status (up to 200 characters each), boolean include_inactive (default false), modified_within_days (1-30), sort (last_modified or release_date), page (1-100), and page_size (1-25, default 10). Unknown query fields and invalid types are rejected.

MCP search always uses case-insensitive SQL substring matching on feature name, description, and product; SQL LIKE wildcards % and _ are supported. It never generates embeddings or implies semantic relevance. The REST API retains its existing semantic-search behavior when embeddings are configured. Dates use inclusive UTC date windows, release dates are quarters, and descending sorts use stable ID tie breaking. Refreshes can shift pages; at page 100, narrow your filters rather than paging further.

Release descriptions are capped at 4,000 characters and other release strings at 1,000, with truncated_fields metadata. History text is also bounded and flagged when shortened. Follow canonical links for full content. Roadmap, blog, and history text is untrusted data, never assistant instructions.

Public reads only: no subscription, watch, feedback, email, arbitrary SQL/URL, or write tools. Vectors, hashes, internal database fields, and personal data are excluded.

Failures and throttling: tool failures set is_error in the Python client (isError on the wire), including NOT_FOUND, BUSY, TIMEOUT, UNAVAILABLE, and RESULT_TOO_LARGE. Respect Retry-After on HTTP 429/503. Budgets per worker are 60 requests/minute, four concurrent reads, 16 KiB request bodies, and a 15-second tool response deadline; scale-out multiplies worker budgets. Host/Origin allowlists apply. GET/DELETE return 405 because this deployment is POST-only.

Operators: see the MCP deployment and client guide for hosting, host/origin settings, Front Door no-cache routing, SQL/retry limits, and the deployment smoke checklist.

History Endpoint /api/releases/history/<release_item_id>

Returns the change history for a single release item, newest first. Each entry shows which fields changed. Possible change descriptions include field diffs (e.g. Release Date 2025-06-01 -> 2025-09-01), Roadmap Item Added, Removed from Roadmap, and Restored to Roadmap.

Changelog /api/changelog

Returns releases grouped by last_modified date with change annotations showing what was modified. Useful for building daily/weekly change reports.

Parameters

  • days - Look-back window in days (default: 30, max: 90)
  • since - Inclusive UTC checkpoint date (YYYY-MM-DD, today through 90 days ago). Returns every recorded tracked-field change event through today, including repeated same-day edits; ignores days and cannot be combined with date.
  • product_name - Filter by exact product name
  • release_type - Filter by exact release type
  • release_status - Filter by exact release status
  • include_inactive - Include removed items (true or 1, default: true)

In since mode, filters use historical event values and results include removals and restorations by default. total_events counts change events (one event may change several fields); total_features counts distinct features. The response also includes since, through, and complete: true. These responses use Cache-Control: private, no-store with no conditional validators. Embedding and blog-only updates are excluded. Recorded history began August 27, 2025.

Catch-up groups transitions by their observed UTC temporal-history day. In this mode, last_modified is that event day, even when the legacy feed date was preserved to suppress removal notifications.

HTTP Caching

All JSON & RSS endpoints emit:

  • ETag - Weak hash for conditional GET (send If-None-Match to receive 304)
  • Last-Modified - Based on build time (collection) or entity timestamp
  • Cache-Control - public, max-age=14400, stale-while-revalidate=3600 (4h fresh, 1h serve-stale)

Caching is handled by Azure Front Door at the CDN edge. The server sets appropriate HTTP cache headers on responses.

Caching & Performance

Summary of caching strategy:

  • CDN Cache (Azure Front Door): Responses cached at edge based on Cache-Control headers
  • Cache-Control: public, max-age=14400, stale-while-revalidate=3600 (4h fresh, 1h stale)
  • ETag: Weak content hash enables conditional GET (304 Not Modified)
  • Last-Modified: Build timestamp for conditional revalidation
